# DuMate 反代插件实施计划

目标：复用现有账号资源、模型发现及 OpenAI 流式协议，将当前 Mac 的 DuMate 企业账号接入 Modweft。

证据：本机 DuMate 1.0.88；当前登录方式为企业版；`/api/dumate-enterprise/app/v1/user`、`user_token`、`model/list-all` 均实测成功；网关地址来自应用配置及模型目录。

## 文件职责

```text
server/plugins/build-in/dumate-auth/  # 独立的 DuMate 提供方
├── plugin.json                     # 标识与明确的网络域名权限
├── main.ts                         # 注册提供方和账号资源
├── resources.ts                    # 导入会话、账号展示、获取和刷新网关令牌
├── models.ts                       # 企业模型目录映射
├── provider.ts                     # 网关鉴权、流式调用和错误分类
├── export-session.mjs               # 只读导出 Mac 当前企业登录会话
├── dumate_test.ts                   # 账号、目录及流式集成测试
├── export-session_test.mjs          # 导出流程与文件权限测试
└── assets/dumate.svg                # 插件图标
server/src/plugin/builtin.rs         # 随应用预装插件
```

不迁移、合并或删除现有模块。保持当前分支；不提交、不发布、不更改 DuMate 数据。

## 边界

首版支持当前已验证的公网企业租户；网络白名单显式列出当前租户和官方网关。其他企业域名需在插件清单授权后使用。个人版和私有化实例没有证据，不做猜测性兼容。会话 Cookie 失效后须在 DuMate 重新登录并导入；网关短期令牌由插件自动续取。模型目录请求失败时明确报错，不返回静态模型回退。

## 1.1.2 本机一键添加（取代手动导出流程）

- 用户只需在 DuMate 登录，然后点击“从本机 DuMate 添加”，无需选择文件、目录或执行脚本。
- `server/src/plugin/local_import.rs`：从固定 Mac 路径只读当前 DuMate 会话并认证解密；只选择当前租户的有效 Cookie；不输出凭证或生成导出文件。
- SDK 导入能力增加 `localSource` 声明；主程序读取后复用原有插件账号解析、资源去重与模型同步。前端通过现有 HTTP 边界调用 `import-local`，仅收到账号数量和同步结果。
- 删除手动导出工具及其测试，DuMate 插件升级 0.2.0，最低应用版本 1.1.2；本机添加模式不再显示批量文件导入。
- 27 项 Rust 插件测试通过，包含 6 项本机账号边界测试；12 项 DuMate Deno 测试通过。
- 显式运行当前 Mac 的真实会话读取与远端模型目录检查通过，不写入实际 Modweft 账号，不执行聊天或业务操作。
- 浏览器验证无文件选择框、点击添加、处理中状态、成功刷新、未登录指引和模型同步失败提示。
- 前端类型检查、i18n 扫描、生产构建及桌面调试构建通过。安装包版本为 1.1.2。

- 最终全量回归：165 项 Rust 库测试通过，1 项需本机账号的测试默认忽略且已单独运行通过；Codex、Antigravity、WorkBuddy 共 42 项回归通过。全量测试的本机网络故障用例受系统代理干扰，设置仅本次测试进程的 `NO_PROXY=127.0.0.1,localhost` 后通过，未修改无关测试代码。
- 1.1.2 镜像完整性、签名、版本、自动读取功能及镜像内应用与构建产物一致性均验证通过；未自动覆盖安装用户当前应用。
